|---|---|---|---|---|
| `E_USAGE` | 配置 / 用法 | 否 | 命令行参数写错、少给必填项或给了子命令不认的选项。 | 按 psychdoc --help 的用法重写命令；跑批脚本改动后先手工跑一遍确认参数。 |
| `E_ARG` | 配置 / 用法 | 否 | 选项本身认得，但取值不合法（方向写错、路径为空、类型不对）。 | 核对该选项的取值范围；批量脚本里通常是变量没赋值就拼进了命令行。 |
| `E_IO` | 配置 / 用法 | 否 | 读不到规则集 / 文书包 / 缓存文件，或写不进输出文件。 | 确认路径拼写与读权限；导出盘满时先清盘再重跑。 |
| `E_INTERNAL` | 配置 / 用法 | 否 | 内部错误类型拿不到稳定码前缀时的兜底（理论上不该出现）。 | 把触发时的输入路径与操作步骤发给信息科；这属产品缺陷，不是配置问题。 |
| `E_CFG_MISSING` | 配置 / 用法 | 否 | EMR_BASE_URL / EMR_CLIENT_ID / EMR_CLIENT_SECRET / EMR_TENANT_ID / WECOM_WEBHOOK_URL 缺失或为空白。 | 在服务账号的环境变量里补齐缺项后重跑；缺项会一次性列全，不会静默降级为本地假数据。 |
| `E_CFG_INVALID` | 配置 / 用法 | 否 | 环境变量都在，但形态非法（URL 不带 https、租户号含非法字符、webhook 不是企业微信地址、PSYCHDOC_LOG_LEVEL 写了不认识的级别）。 | 对照接口规范改环境变量的写法；本产品不做任何猜测式修正（不补 https://，不把未知日志级别回落成默认）。 |
| `E_DATA_DIR` | 配置 / 用法 | 否 | 定不出用户数据目录（HOME / APPDATA / XDG_DATA_HOME 都没有）。 | 显式设置 PSYCHDOC_DATA_DIR 指向一个可写目录后重跑。 |

| `E_CACHE_CORRUPT` | 配置 / 用法 | 否 | 增量缓存文件里的内容不是本产品写的形态（被别的工具改过或写到一半断了）。 | 删掉该缓存文件重跑一次全量；缓存被拒时本产品宁可全量重算，也不拿半份缓存凑结论。 |
| `E_CACHE_SERIALIZE` | 外部依赖 | 是 | 增量缓存写不出去（磁盘满、路径不可写）。 | 清盘或换缓存路径后重跑；缓存写失败不影响本次审查结论，只影响下次是否重算。 |
| `E_RULESET_INVALID` | 配置 / 用法 | 否 | 规则集加载期强校验没过：引用未定义文书类型、同层码重复、覆盖成环、缺规范依据、豁免谓词非法。 | 按报错里的文件名与行号改 YAML；本产品在此时零条规则放行，绝不降级为「无规则=通过」。 |
| `E_NO_RULE_BASIS` | 配置 / 用法 | 否 | 某条规则没有写院内规范条款依据。 | 在规则集里给该码补 basis 字段；没有依据的诊断不允许贴进交办单。 |
| `E_EMPTY_MESSAGE` | 配置 / 用法 | 否 | 规则消息正文为空（即使写了依据）。 | 补 message 正文；空文案会让交办单上出现一条只有码没有说明的整改要求。 |
| `E_TYPE_MISMATCH` | 配置 / 用法 | 否 | 数值字段遇到非数字文本（全角数字、空串等）。 | 文书侧修正导出或规则侧收窄适用范围；全角日期是唯一会给补写预览的分支，其余只给依据。 |
| `E_DATE_PARSE` | 配置 / 用法 | 否 | 日期 / 日期时间字段遇到非法格式。 | 确认导出系统的日期格式（FHIR 要求 ISO8601）；低精度（只到日 / 只到时）会走另一条降级路径。 |
| `E_REGEX_INVALID` | 配置 / 用法 | 否 | 规则集里的正则表达式编译不过。 | 修正 YAML 里的 pattern；本产品返回错误而不是抛异常，规则集不会被静默跳过。 |
| `E_PATH_INVALID` | 配置 / 用法 | 否 | 字段路径写不出「件 / 段 / 段内键」三级形态。 | 按 `s1.患方签字` 的写法改条件里的 path。 |
| `E_OPERAND_MISMATCH` | 配置 / 用法 | 否 | 算子与操作数形态对不上（如 between 配了文本操作数）。 | 把操作数改成与算子匹配的形态；本产品不猜。 |
| `E_DIMENSION_MISMATCH` | 配置 / 用法 | 否 | 数值比较跨了量纲（字段是「小时」、条件写的是「毫克」）。 | 统一量纲再比；同量纲的单位会先换算（2 小时 == 120 分钟）。 |

| `E_BUNDLE_JSON` | 配置 / 用法 | 否 | 文书包正文不是合法 JSON（多半是 HTML 登录页或导出中断的半截文件）。 | 重新导出；若导出走的是院内接口，请先确认拿到的是 Bundle 而不是错误页。 |

| `E_ENCOUNTER_ALIAS_MISSING` | 配置 / 用法 | 否 | 件上没有住院别名，无法归组。 | 检查导出是否带 identifier；跨件时间序与归档核齐都以住院别名为键。 |
| `E_DOC_ID_DUPLICATE` | 配置 / 用法 | 否 | 同一份导出包里出现两个相同 doc_id（多半是跨系统同名导出）。 | 人工确认后删掉其中一份；本产品既不合并也不取第一条，两条都进人工队列。 |
| `E_BIND_NOT_CONFIDENT` | 配置 / 用法 | 否 | 跨文书实体绑定不唯一（同名文书多份），无法确定按哪一份参与时间序判定。 | 人工在归档核齐视图的待确认队列里指定；绑定不唯一时整对跳过，不猜。 |
| `E_BUNDLE_SHAPE` | 配置 / 用法 | 否 | 输入不是 FHIR R4 Bundle（resourceType 不是 Bundle、entry 不是数组、正文不是 JSON）。 | 确认导出的是 Bundle 而不是单条 Composition；本产品不会把非法输入当成空包。 |
| `E_STATE_JUMP` | 配置 / 用法 | 否 | 件级状态非法跳变（如「缺失」直接跳「可归档」）。 | 按缺失→草稿→已建件→已收→可归档逐步推进；非法跳变不改变任何既有状态。 |
| `E_STATE_UNKNOWN` | 配置 / 用法 | 否 | 库里没有这件，无法推进它的状态。 | 先让本轮审查登记这件，或确认件 id 是否写错。 |
| `E_SPAN_REVERSED` | 配置 / 用法 | 否 | 区间起点大于终点。 | 属产品内部缺陷，请把触发输入报给信息科；正常路径不会产生反向区间。 |
| `E_SPAN_OUT_OF_BOUNDS` | 配置 / 用法 | 否 | 区间越出所在段落的文本长度。 | 属产品内部缺陷，请把触发输入报给信息科；段落切分与字段定位本应恒在界内。 |
| `E_DB_IO` | 外部依赖 | 是 | sqlite 操作失败（磁盘满、文件被占用、约束冲突）。 | 确认磁盘空间与目录权限后重跑；本产品不会因为写库失败就改口说「已写回」。 |
| `E_SCHEMA_EMPTY` | 配置 / 用法 | 否 | 目标库是空文件但不是本产品建的库（零页 / 已被别的工具占用）。 | 换一个库路径，或备份后删掉该文件让本产品重建。 |
| `E_SCHEMA_TOO_NEW` | 配置 / 用法 | 否 | 库文件版本比当前程序新（另一台机器或更新版本写过）。 | 用与该库匹配的版本打开；不要降级写同一个库，否则会把新版本的数据写坏。 |

| `E_REGRESS_EMPTY` | 配置 / 用法 | 否 | 用例集一条用例都没有。 | 补用例；空用例集会「全绿」成假通过，覆盖矩阵为 0 也会被报出来。 |
| `E_REGRESS_NO_ID` | 配置 / 用法 | 否 | 用例没有 id。 | 给每条用例一个稳定 id，便于按用例定位失败。 |
| `E_REGRESS_DUP_ID` | 配置 / 用法 | 否 | 用例集里出现重复 id。 | 改掉重复 id；重名会让「哪条用例失败」无法回答。 |
| `E_REGRESS_CODE_SHAPE` | 配置 / 用法 | 否 | 用例里的规则码不是 QC-PSY-nn 形态。 | 核对规则集里的码与用例期望里的码是否同一套。 |
| `E_REGRESS_NO_FIXTURE` | 配置 / 用法 | 否 | 用例没有 given.fixture（本轮按用例驱动回归，无默认夹具）。 | 给用例指定夹具文件名。 |
| `E_REGRESS_POSITIVE_NO_CODE` | 配置 / 用法 | 否 | 正例用例跑完没命中期望的码。 | 先看是该改规则集还是该改用例；本产品不自动改期望值。 |
| `E_REGRESS_NEGATIVE_WITH_CODE` | 配置 / 用法 | 否 | 反例（合规件）跑出了命中——误报守卫拦下了。 | 收窄规则的适用范围或修实现；误报比漏报更伤——没人再敢信这份清单。 |
| `E_REGRESS_FIXTURE_MISSING` | 配置 / 用法 | 否 | 用例点名的夹具文件在磁盘上找不到。 | 确认 --root 指向项目根，或夹具是否被清理阶段删掉。 |
| `E_REGRESS_FIXTURE_UNPARSABLE` | 配置 / 用法 | 否 | 夹具文件读得出来但解析不了（不是合法 Bundle）。 | 确认夹具没被改坏；脏数据用例请用夹具目录里的 dirty/ 那一批。 |
