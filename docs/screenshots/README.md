# 实测截图：生成命令与夹具来源

本目录下 4 张 PNG 全部是**运行期真跑出来的**，不是设计稿、不是概念图、
也不是事后拼的效果图。生成入口只有一个脚本：

```bash
cd psych-inpatient-doc-audit
PYTHONPATH="$PWD:$PWD/bindings" python3 scripts/capture_screenshots.py
```

脚本用 `QScreen.grabWindow(winId)` 抓**窗口自身**的绘制结果
（不是抓整屏：传 widget 会走到「按坐标抓屏幕」分支，截回来的是桌面）。
三态窗口全部走 `MainWindow.load_paths()` → `scan_queue` → `review_batch`
这一条真实主路径，job 在 `QThreadPool` 上跑，脚本转事件循环等到
job 收完才截图——不等就是空壳窗口，脚本宁可 `SystemExit` 也不出图。

截图期间 `PSYCHDOC_DATA_DIR` 与 `PSYCHDOC_CACHE` 被指到 `.shot-work/`，
不写用户数据目录，也不污染项目子目录。

## 关于 `QT_QPA_PLATFORM`

脚本默认 `offscreen`：真实显示器上抓屏会把系统弹窗（macOS 的
「Terminal 请求屏幕录制」授权框、输入法候选窗）一起框进来，那不是产品界面。
offscreen 下抓的仍是**同一个窗口**经 Qt 真实布局与 QSS 绘制的结果，
只是没有系统装饰层（因此图里没有窗口标题栏那一条）。

要带系统装饰的本机截图：

```bash
QT_QPA_PLATFORM=cocoa python3 scripts/capture_screenshots.py
```

代价是系统弹窗可能被框进来。

## 与视觉目标的关系

`docs/concepts/visual-target.md` 是**目标**（Phase 1 定的配色、版式、
信息层级），本目录是**实测**。两者不可能逐像素一致：目标卡描述的是
「托盘角标浮在菜单栏右侧」这类系统层效果，而 Qt 窗口自身的抓取拿不到
那一层。README「概念 / 实测对照」一节按这个口径写差异。
